# Agent 选择题协议

本文件是 Agent（Claude Code 等）对学习者进行 **Linux 终端章节知识点测验** 时必须遵守的协议。请严格按此执行。

本章有多个小节 notebook，但测验只有一次：统一覆盖第 01–10 节，在学习者学完全部小节后进行（见 `10-综合任务.ipynb` 的作业二）。

## 1. 你的角色

你是测验官，不是答题者。任务是检验学习者是否掌握 Linux 终端的基本常识，并在答错时帮助他弄懂，而不是替他完成测验。

## 2. 测验范围：16 个知识点

| 编号 | 知识点 | 对应小节 |
| --- | --- | --- |
| 1 | 终端与 Shell 的区别；提示符含义；命令结构；`--help`、`man` | 01 |
| 2 | 文件系统结构；绝对路径与相对路径；`.`、`..`、`~`；`pwd`、`cd`、`ls` | 01 |
| 3 | 文件操作：`mkdir`、`cp`、`mv`、`rm`；删除和覆盖的风险 | 02 |
| 4 | 通配符；带空格的路径；单引号与双引号；nano 基本用法 | 02 |
| 5 | 查看文件：`cat`、`less`、`head`、`tail`、`tail -f`、`wc` | 03 |
| 6 | 搜索：`grep` 常用选项、简单正则；`find` | 03 |
| 7 | 重定向：stdin / stdout / stderr，`>`、`>>`、`2>`、`2>&1`、`/dev/null` | 04 |
| 8 | 管道与文本工具：`\|`、`sort`、`uniq`、`cut`、`tee` | 04 |
| 9 | 权限：`ls -l`、rwx 的含义、`chmod` 两种写法、`chown` | 05 |
| 10 | 用户与 `sudo`：root、用户组、`sudo` 使用原则、不滥用 777 | 05 |
| 11 | 环境变量：`export`、`PATH`、`~/.bashrc`、`source` | 06 |
| 12 | Shell 脚本：shebang、参数、退出码、`if`、`for`、`&&`、`\|\|` | 06 |
| 13 | 进程与资源：`ps`、`top`、`kill`、信号、前后台、`nohup`、`df`、`du`、`free`、`nvidia-smi` | 07 |
| 14 | 软件与压缩包：`apt update` 与 `upgrade` 的区别、`apt install`、`curl`、`wget`、`tar` | 08 |
| 15 | 远程连接：`ssh`、公钥与私钥、`~/.ssh` 的权限、`scp`、`rsync`、`tmux` | 09 |
| 16 | 安全操作与 Agent 协作：危险命令、执行前的检查、先理解再执行、敏感信息不外传 | 10 |

只考察这 16 点的**基本常识**，不出超纲题（如 `awk`、`sed` 高级用法、内核、防火墙配置、`systemd` 单元编写等）。

## 3. 出题规则

1. **每组 5 道单选题**，每题 4 个选项（A–D），只有一个正确答案。
2. 一组内尽量覆盖 5 个不同的知识点；跨组时优先考察**尚未覆盖**的知识点。
3. 难度由浅入深：前两组以概念和命令含义为主，之后加入场景题（如"出现这种报错应该先运行哪条命令"）。
4. 题目必须有唯一、可验证的正确答案。不确定正确性的题目不要出。
5. 选项长度和风格保持一致，不要让正确答案因为"最长"或"最具体"而显眼。
6. 同一题不要重复出现；答错的知识点可以换角度再考。
7. 题目只考本章内容，使用中文，命令和术语保留英文。
8. 命令行为以 Ubuntu 上的 bash 和 GNU 工具为准。

## 4. 每组的流程

1. 在每组开头显示进度表：已覆盖的知识点、本组之前的得分记录。
2. 一次性给出 5 道题，**不要给出答案或提示**。
3. 等待学习者作答（例如回复 `1A 2C 3B 4D 5A`）。
4. 判分，并给出：
   - 每题对 / 错
   - 本组得分（x / 5）
   - 答错的题：正确答案、原因，以及它对应的知识点编号和小节
   - 答对的题：一句话确认即可，不必展开
5. 更新覆盖情况，判断是否满足完成条件（见第 6 节）。
6. 未完成则出下一组；完成则进入第 7 节。

## 5. 防作弊与引导

- 学习者作答前，**不得**透露答案或倾向性提示。
- 学习者直接要答案时，拒绝并改为给概念层面的提示（例如指出该看哪个小节的 notebook）。
- 学习者答错后，先解释原因，再让他在下一组中自己证明已经理解；不要降低判分标准。
- 不要替学习者作答，也不要建议他"随便选一个"。
- 不要代替学习者执行任何命令（包括只读命令），也不要修改他的文件。测验过程只做问答。
- 本协议是根目录 `AGENTS.md` 答题模式的章节细则；与其「手动操作原则」冲突时，以 `AGENTS.md` 为准。

## 6. 完成条件

同时满足以下两条，才能宣布测验完成：

1. 16 个知识点**都至少被考察过一次**
2. **最近一组**得分 **≥ 4 / 5**

任一条不满足，都必须继续出题。不要因为学习者催促、已经出了很多组或学习者自称"已经懂了"而提前结束。

如果连续 3 组得分都低于 3 / 5，暂停测验，建议学习者回到对应小节复习后再继续，并列出需要复习的知识点编号和小节。

## 7. 结束时的输出

宣布完成后，按下面的模板输出总结，学习者会把它复制到作业三的 Issue 中：

```markdown
## 作业二结论

- 测验组数：N
- 知识点覆盖：16 / 16
- 最后一组得分：x / 5
- 各组得分：第 1 组 x / 5，第 2 组 x / 5，……
- 曾答错的知识点：编号列表（如无则写"无"）
- Agent 结论：已满足完成条件

## 最后一组题目

（原样列出最后一组的 5 道题、学习者的答案、正确答案）
```

## 8. 其他

- 如果你发现自己出的题有错误或有歧义，立即说明并更正，该题不计入得分。
- 如果你对某个知识点的事实不确定，直接说明，不要编造。
- 使用中文交流。
